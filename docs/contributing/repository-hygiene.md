# 仓库文件放置、测试和自动化维护规范

本文是本仓现行维护规则。具体目录是本仓选择，不是 Go 社区唯一标准。

## 1. 总则

本仓长期维护真实产品源码、必要回归、当前开发/运维入口和少量重要决策。一次性 agent 过程材料不自动成为产品源码；已有文件也不因名字含 test/lab/日期就自动无价值。

新增文件前，agent必须明确：用途、消费者、默认是否执行、是否产生外部副作用、长期保留还是临时使用。当前任务只授权分析时，不创建远端提交、不执行部署或数据库操作。

不得为了消除错误而删除关键测试、缩小必跑范围、关闭安全检查或使用重试直到绿。经批准的功能退役可以删除其专属测试，但应说明退役边界，不能宣称覆盖未变或缺陷已经修复。

## 2. 放置表

| 内容 | 位置 | 规则 |
|---|---|---|
| Go业务实现 | 当前`app/.../internal`或`pkg`职责包 | 无仅测试的构造器、控制API或模拟资源状态机 |
| 包级单元/集成测试 | 实现旁`xxx_test.go` | 同包或外部`xxx_test`，按真实可见性选择 |
| 同包测试helper | 同目录`fixture_test.go`等 | 使用小写helper和`t.Helper`；无生产导出后门 |
| 跨服务内部包的共享fixture | `app/admin/service/tests/testutil` | 普通`.go`允许，但只能由测试导入；不复制生产业务初始化 |
| 真实跨仓合同测试 | `app/admin/service/tests/contracts/<topic>` | `_test.go`；显式选择；与真实依赖版本绑定 |
| 静态测试输入 | 对应测试附近`testdata` | 小型、可重复、说明来源；不是运行日志/完整dump |
| CI执行脚本 | `scripts/ci` | 负责检查/构建/环境/结果，不承载业务断言状态机 |
| 脚本测试 | `scripts/tests` | Python用`test_*.py`，Shell使用明确测试入口 |
| 日常开发工具 | `scripts/dev`或已公开稳定入口 | 版本固定、无默认全局安装；路径变更更新消费者 |
| 真实运维/诊断工具 | `scripts/ops`及已存在`deploy`/`backup`入口 | 数据库/发布操作需明确目标与授权 |
| CI 专属库准备 SQL | `scripts/ci/sql` | 只用于独占测试实例，不冒充生产运维脚本 |
| 显式版本数据步骤 | `sql/data` | 在对应结构迁移之间显式执行；Atlas 不自动读取 |
| 人工实验 | `scripts/experiments/<topic>` | opt-in；单份README；显式参数；可完整清理 |
| 代码生成配置 | `api/`、`tools/config/` | 配置不放历史回执目录；版本真相不复制多份 |
| 现行合同与操作指南 | `docs/contracts`、`docs/operations`、现有指南 | 一项内容一个权威入口 |
| 长期重要决策与历史索引 | `docs/history/README.md`或简短已接受决策 | 只保留结论/取舍/固定来源，不复制全部执行过程 |
| 运行日志/截图/测试JSON/二进制/覆盖率 | Git忽略的`.artifacts`或仓库外、CI artifact | 默认不提交；明确保留期和敏感信息边界 |
| agent输入与临时工具 | Git忽略的`_agent`/`.scratch`或仓库外 | 不成为生产或生成依赖，不自动加入提交 |

不得在根目录随意创建`Txx-*`、`Rxx-*`、`fix-final-v2`、`handoff-final`等新过程材料树。任务编号可以出现在临时输出目录或PR摘要中，不成为长期源码布局。

## 3. Go测试规范

### 3.1 文件名与包边界

Go测试函数放在 `_test.go`。默认与被测代码相邻；`internal`不是“不能放测试”的标记。测试私有方法使用同包测试，不为方便测试新增生产`ForTest`方法。

**跨包例外必须正确理解：** 被另一个包导入时，普通包不包含自身`_test.go`文件。禁止只将`repo_testkit.go`改名，然后要求`service`测试继续调用`data.NewXxxRepoForTest`。共享设施需要普通`.go`时，放明确`tests/testutil`，以正式依赖图禁止生产消费者；不是新增`test`构建标签就自动隔离。

不要把测试移到Go `internal`可见范围以外后去放宽生产包可见性。Ent等生成器自带的标准测试辅助由生成合同管理，不手改后缀或批量删。

### 3.2 被测对象

fixture只负责Context、数据库、证书、时钟、连接与必要依赖。测试应调用真实Repository/Service构造和方法；不得复制生产字段初始化、mapper/converter或业务`init()`来构造一套“更容易通过”的替身。

纯接口替身只模拟外部协议边界，必须小型、场景限定。禁止为了测一个Gov方法，建立自己的owner/provider双数据库、长期控制服务与恢复算法。已有可维护跨仓协议fixture有明确价值时可以保留，但结果不能冒充真实外部系统验证。

不使用`isTest`、环境变量或仅测试构造器绕过鉴权、租户隔离、事务、真实生命周期。确需改善可测性，做正常依赖注入/生命周期设计，独立说明行为边界。

测试静态 SQL 放相邻 `testdata/`，跨包共享设施仍只放 `app/admin/service/tests/testutil`；`internal` 可以容纳测试。SQL 文件名不靠 `_test.sql` 获得 Go 构建隔离。版本迁移、正式 bootstrap、数据升级、运维 SQL、测试输入和生成快照各有不同消费者，不能相互替代；破坏性夹具不得混入正式运维步骤。

### 3.3 资源和时序

使用`t.TempDir`、`t.Cleanup`及有界Context。资源创建成功立即登记清理；一次资源明确一个关闭责任人。后台goroutine通过channel报告结果，由测试主goroutine作Fatal/require判定。

测试就绪、取消、完成、资源收尾分别观察；不得只sleep后假设就绪，不以全进程goroutine数量回到基线替代本测试资源证明。必要的Eventually用于真实最终一致性而非放宽结果；固定上限且失败保留诊断。

测试期望固定输入、明确时区和可解释随机性。不把两次time.Now作精确相等断言，不把随机碰撞试验当数学上必然不冲突。修改环境变量的测试串行，保留已有环境，不读真实凭据。

### 3.4 数据与安全

快速测试不自动连接共享PG、Redis、Kubernetes或公网。集成套件被明确选择后，必需环境缺失应失败；不通过Skip将未测安全边界包装成成功。

PG/Redis/namespace必须有本run归属。禁止默认业务DSN、固定旧管理员密码、任意localhost实例、共享库TRUNCATE。迁移管理员与业务测试运行角色分离；不能为了通过测试提高权限或删除约束。

SQLite可用于适合它的CRUD测试；不能据此声称覆盖PostgreSQL行锁、JSON约束、迁移或并发语义。需要真实mTLS/数据库的断言保留真实机制。

### 3.5 保留、重构、删除

测试的价值按被测真实行为、断言有效性、可重复性、成本判断，不按数量。表驱动合并重复用例允许，必须保留原有有效分支。无断言展示、已退役功能、不可再取得的指定历史样本入口可在退役记录中删除。

失败测试先判断环境/夹具/真实缺陷；不能仅因失败就标“没必要”。旧迁移等价校验不必永久作为日常产品测试，当前缺陷复现与未验证范围应另有简短记录。

## 4. CI与脚本规范

`.github/workflows`只编排触发、环境、脚本和artifact。Make提供薄入口；检查实现位于`scripts/ci`，Go业务断言位于Go测试。不得维护三份不同的版本表或测试名单。

当前单 workflow 保留 `checks`、`integration`、`generation` 三个 job，分别委托 `make check`、`make test-integration`、`make check-generated`；`make verify-ci` 串行调用三者。Ent 参数只在本仓 `gow` 有一份运行时来源，生成门禁复用正式 `make gen`。消除重复命令要先核对构建标签、测试集合及必要的独占资源；race、关键测试、生成保护和安全扫描不得因命令数减少而缺失。

每个 job 保留一份含源码 SHA、真实退出码、脱敏日志和必要测试 JSON 的工件。安装与数据库准备失败时主检查记为 `not_started`，取消不算通过；同 PR 新提交可取消旧 run，main run 保持独立。日常开发由自动工件负责，不常设阶段回执或逐文件审批台账。

脚本必须能从任意工作目录定位repo（以脚本真实位置或显式参数），有清晰usage、错误码、必要环境验证。Shell适合短编排，复杂JSON/条件逻辑用Python标准库等已有工具；不引入无必要框架。

保存子命令真实退出码，不取最后一个tee/echo的状态。使用管道时正确启用pipefail并取适用进程状态；命令失败不得继续打印PASS。清理失败与主命令失败分别记录。

资源按本run唯一ID/label/目录管理，EXIT/INT/TERM能清理已创建资源；禁止docker prune、按宽泛名字kill、信任陈旧PID、不验证owner便删除容器。已有外部资源不得静默接管。

常规PR与main检查保持自动化；避免对同一普通开发分支的push和PR重复运行重任务。脚本自身、布局/生成检查及必要安全/并发测试都必须有可解释覆盖；不得以部署成功代替关键回归。

修改CI名称/作业ID时核对既有保护要求，不能擅自更改仓库权限或绕过检查。默认不得部署、发布镜像、打tag或操作业务数据库。

正式部署走容器与显式 Atlas 步骤；本仓不再维护主机自动安装、全局 Go 安装和 PM2 启动入口。开发者仍可直接 `go run`、`go build` 和 `go test`。仓库退役不授权卸载机器软件、停止现有服务或修改主机配置。

## 5. 实验规范

实验必须有明确使用者、目标与退出条件。保留实验放 `scripts/experiments/<topic>`；README列出真实被测对象、替身范围、所需版本、显式目标、授权与清理方式。

禁止固定旧账号、SSH主机、集群context、namespace、NodePort、PID或容器ID作为可执行默认值。没有参数时返回usage或只读预检，不自动使用“之前跑过的环境”。旧实验帮助脚本的跨目录引用必须合并清楚，不借用已暂停实验的隐藏函数。

一次性探针完成后删除；确需保留其断言则转成语言测试。禁止通过`//go:build ignore`或藏到internal把临时程序永久留在产品树中。受支持的开发CLI可保留普通main，但须有正式职责与调用入口。

## 6. 文档与证据规范

README是项目入口，development是开发步骤，AGENTS是agent规则，专题合同各有唯一来源。CLAUDE等只引用，不复制长规则。

任务过程只在PR/临时输出中记录一次：变更范围、SHA、实际命令/退出码、未验证事项和链接。禁止每轮会话新增一份完成/交接/自我纠错台账提交。

原始日志、截图、test JSON、源码ZIP、数据库dump不属于现行开发文档。CI artifact承担短期执行证据；必要长期材料放可靠归档并留摘要、来源与固定提交索引。不得将重要许可声明仅留在已移出的源码ZIP中。

历史退役不等于历史验收通过。保留R6等真实未验证结论；删除不可运行的历史测试入口时，不恢复寻找样本的无限任务，也不伪造新fixture冒充原数据。

## 7. Agent提交前必须回答

- 新文件放在表中哪个位置？没有合适位置，是确有新职责还是一次性材料？
- 实际调用者是谁？是否进入正式server/admin依赖图？
- 删除了哪些能力/断言，哪些只是重复或退役实验？剩余关键保证在哪里验证？
- 生成、脚本、CI、测试数据与文档引用是否同时更新？
- 命令在哪个SHA执行，哪些通过，哪些失败/跳过/未运行？
- 是否包含秘密、测试运行结果、二进制或不该跟踪的临时文件？

最终保留一份简短结果即可。禁止自动`git add .`夹带任务材料；禁止改写历史、强推或操作用户共享环境。实现范围扩大或真实业务合同需变化时，给出具体差异；不要以“目录整理”作为授权来源。

## 8. 最小自动约束

现行CI应接入轻量布局检查：跟踪文件路径、正式依赖图、已退役入口引用、测试与fixture位置。发现未知结构时给出具体路径和原因，不通过目录级宽泛豁免过关。

不要求永久维护逐方法/逐文件批准表；本次设计的全路径清单用于整改分析，不作为以后每次开发必须更新的账本。
